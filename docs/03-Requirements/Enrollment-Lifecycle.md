# Enrollment Lifecycle & Definition
**Version:** 1.0.0  
**Status:** Approved  
**Domain Aggregate:** Enrollment  

## 1. Purpose
This document defines the lifecycle, statuses, and rules governing the `Enrollment` aggregate in the ProjectHub domain. It acts as the single source of truth for the Enrollment State Machine.

## 2. Enrollment Statuses
| Status | Description | Is Terminal? |
|---|---|---|
| **Pending Payment** | Registration created, awaiting payment confirmation. | No |
| **Enrolled** | Student is officially registered and active in the class. | No |
| **Cancelled** | Registration cancelled before class starts or payment. | Yes |
| **Withdrawn** | Student voluntarily withdrew after enrollment. | Yes |
| **Completed** | Student successfully passed the class (Attendance ≥ 70% & Grade ≥ 12). | Yes |
| **Failed** | Student did not pass the class. | Yes |

## 4. Business Rules & Invariants
1. Every `Enrollment` must always have exactly one `Status`.
2. **Initial Status Logic:**
   - If `Class.Tuition == 0` → Initial Status = `Enrolled`.
   - If `Class.Tuition > 0` → Initial Status = `Pending Payment`.
3. `Completed` and `Failed` are **Terminal States**. No further transitions are allowed.
4. `Cancelled` and `Withdrawn` terminate the enrollment lifecycle.
5. Once an enrollment reaches a Terminal State, it cannot transition back to `Enrolled`.

## 5. Enrollment Date (Audit Field)
**Definition:** The exact date and time when the `Enrollment` record is created.
**Rules:**
- Automatically generated by the system upon creation.
- **Immutable:** Cannot be edited or deleted.
- Stored in UTC format.
- Used for reporting, auditing, and future refund calculations.
