# Enrollment Definition

Version: 1.0.0
Status: Approved Baseline

---

# 1. Definition

Enrollment represents the official registration of a Student in a specific Class.

Enrollment is an academic/operational relationship.
Payment is a separate concern.

---

# 2. Enrollment Status

| Status | Description | Terminal |
|---|---|---|
| Registered | Registration has been created successfully. | No |
| Studying | Student is actively participating in the Class. | No |
| Completed | Student successfully completed the Class. | Yes |
| Cancelled | Enrollment was cancelled before completion. | Yes |
| Dropped | Student stopped participating before completion. | Yes |
| Failed | Student did not successfully complete the Class. | Yes |

---

# 3. Status Lifecycle

```text
Registered
    │
    ▼
Studying
    │
    ├────────────► Completed
    │
    ├────────────► Dropped
    │
    ├────────────► Failed
    │
    └────────────► Cancelled
```

The exact transition triggers will be refined in the relevant future use cases.

---

# 4. Initial Status

Every newly created Enrollment starts with:

`Registered`

Tuition amount does not change the Enrollment Status.

Payment processing and payment state belong to the future Payment module.

---

# 5. Business Rules

- Every Enrollment must always have exactly one Status.
- Initial status is `Registered`.
- An Enrollment is unique for a `(StudentId, ClassId)` pair.
- Enrollment cannot be created when Class status is not `Open`.
- Class capacity must not be exceeded.
- Session conflicts must be checked before creation.
- `Completed`, `Cancelled`, `Dropped`, and `Failed` are terminal states.

---

# 6. Enrollment Date

Enrollment Date represents the exact date and time when an Enrollment record is created.

It is:

- Automatically generated by the system.
- Immutable.
- Stored using UTC.
- Used for reporting and auditing.
- Intended for future financial/refund calculations.

Example:

```text
2026-08-03 14:35:18 UTC
```
